RE-CHECK OF EARLIER FINDINGS
- 1 (numbers pooled across fields): FIXED in the sense that matters. Prose may not contain a digit, so numbers are no longer pooled. Every number the user reads is rendered by `ClaimRendering` from the verified assertion (ClaimText.scala:130-162). The tests are non-circular: ClaimBindingSpec:52-75 asserts UNSUPPORTED for "6 publications", "4 coauthors and 4 papers" and "2010 coauthors". They would pass the old code only if the digit rule were removed. The digit-free rule is not complete, though (new findings A and B).
- 2 (relations in prose): PARTLY FIXED. The relation lexicon and the INTERPRETATION typing are real (ClaimVerificationAgent.scala:129-166, ClaimBindingSpec:86-126). The lexicon is applied only in `verifyClaim`, not to the summary or the uncertainty note (new finding A). The lexicon also has gaps (finding C).
- 3 (verify what is shown): FIXED. `ShownText.normalize` runs NFKC, strips invisible characters and runs NFKC again, and verification runs on that string (ClaimVerificationAgent.scala:129). `assemble` refuses any display text that does not survive normalization unchanged (AnswerWorkflow.scala:616). Tests at ClaimBindingSpec:137-166 cover ZWSP, fullwidth, glued and Arabic-Indic digits and a split ID. Residual: Roman numerals, see finding B.
- 4 (replay returns a different answer): FIXED. AnswerWorkflow.scala:744-766 loads the stored record. A different hash gives a non-retryable `IdempotencyConflict`, and an unreadable record gives a retryable failure. `AnswerHash.text` covers the summary, the claims and the uncertainty (WorkflowSupport.scala:141-146), and interpretations are in the uncertainty, so the hash covers them. ClaimBindingSpec:191-215 would fail on the old code. Residual: the replay still re-runs the model, so a nondeterministic model can produce a conflict on a legitimate replay. The engineer disclosed this and it is not a defect.
- 5 (rounding tolerance): FIXED. The half-unit rounding is gone, real values compare within 1e-6 (ClaimVerificationAgent.scala:254-260), and the value is rendered exactly (`show`, lines 295-303). Test at ClaimBindingSpec:170-187.
- 6 (silent drop of a corrupt candidate): FIXED. `decide` rejects any NaN, infinite or out-of-range confidence with `CANDIDATE_CONFIDENCE_INVALID` (ResearcherResolverAgent.scala:124-133). `Rejected` is abstainable (AnswerWorkflow.scala:122-124, 209-220), so it becomes an abstention. The tests (ResolverRunnerRepairSpec:25-42) are non-circular. A candidate beyond `maxCandidates + 1` is never seen, which is acceptable. There is no workflow-level test of the abstention path, which is a minor gap.
- 8 (circular benchmark): PARTLY FIXED. An adversarial set was added (BenchmarkSpec:416-519) and it mutates subject, object and window. `factsOf` at BenchmarkSpec:336-337 still derives the grounded facts from `EvidenceFacts.ofBundle`. Parser-level circularity is reduced, not removed. The 30 questions still all use structured fields, so the model planner path is not benchmarked. The report path is still cwd-relative. All of this is minor.
- 10 (unbounded thread pool): FIXED. `StageRunner` uses a `ThreadPoolExecutor` with 16 threads and a queue of 64, and queue overflow gives a retryable `RejectedExecutionException` result (WorkflowSupport.scala:157-192). A timed-out queued stage is removed from the queue. `future.cancel(true)` followed by `pool.remove(future)` is correct, because the `submit` future is a `FutureTask`, which is a `Runnable`. The test (ResolverRunnerRepairSpec:49-69) fails on a cached pool. Residual: 16 stuck calls make every later stage wait and then time out as retryable. This is bounded and acceptable. Queue wait time counts against the stage timeout, also acceptable.
